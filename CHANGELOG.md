# Changelog

All notable changes to this project are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) where applicable. Skill content versions are tracked upstream.

## [Unreleased]

### Added
- **Incremental git transport for remote installs.** The library is now a git partial clone (`--filter=blob:none`) with a cone-mode sparse checkout in the data directory, `${XDG_DATA_HOME:-~/.local/share}/awesome-skills/library` (`%LOCALAPPDATA%\awesome-skills\library` on Windows), instead of a full `main` tarball downloaded into memory on every run. An update fetches only new commits and trees; only the blobs of selected skills whose git tree changed are downloaded, through a sparse checkout narrowed to exactly those skills and narrowed back afterwards. With nothing changed a run is one `git fetch`, writes nothing (no file, mtime or manifest change), and prints the single line `Already current; selection preserved.`
- Per-skill change detection by git tree id: ownership records now store the `tree` they were installed from, and an unchanged, present skill costs one `lstat`. Destination hashing happens only for entries that changed, are missing, or are (de)selected, so updating one changed skill in a 2,233-skill Claude install took 0.55 s against a local `file://` remote (no-op: 0.16 s).
- `library_index.json`, a committed full-library index (every source ID's frontmatter name and description) generated by `scripts/sync_skills.py` (also `--index-only`) and verified in CI. `--list`, `--search` and the router read it with `library_sources.json`, so searching never downloads skill bodies; a skill missing from the index is skipped with a warning.
- `install.ps1`, a native Windows bootstrap (PowerShell 7, also 5.1) with the same flags as `install.sh`. `scripts/install_skills.py` runs on native Windows: no unconditional `fcntl` import, an `msvcrt` lock, `git -c core.longpaths=true`, extended-length paths for deep skill trees, plain copies, junctions treated like symlinks.
- The installer's own lock is held across fetch, planning and apply; a concurrent run exits with status `75`. Exit codes are now `0` success (including already current), `1` error, `2` usage error, `3` a person must act (an interrupted update or a mass removal), `75` locked.
- Env overrides `SKILLS_DATA_DIR`, `SKILLS_REPOSITORY_URL` and `SKILLS_INSTALLER_URL`; tests use a local bare repository served over `file://` and never reach the network.
- Unattended-run robustness. An update killed mid-apply is undone automatically at the start of the next run (exit `3` with the `--restore` command when a later edit prevents that); an exception while moving entries rolls back at once. Under the lock, stale git `*.lock` files and partial clones are removed, a dropped or stalled transfer is retried once, and only a clone git reports as damaged is moved to `library.broken-<time>` and cloned again once (older broken copies are deleted after that clone works); a full disk or a failed blob download is reported, not healed. Library entries that cannot be checked out everywhere, or are missing from the index, are skipped with a warning and installed copies of them are frozen; a skill whose copy fails to prepare or verify is skipped while the others update, and the run exits `1`.
- A stalled connection can no longer keep the lock: git transfers abort below 1000 bytes/s for 60 s (`GIT_HTTP_LOW_SPEED_*` override) and, unless ssh is configured for git, ssh runs with `BatchMode=yes`, `ConnectTimeout=30` and keepalives. Where `flock` fails as unsupported (NFS or Lustre homes), an `O_EXCL` lock file with a random token and start time takes its place: stale only after 6 hours, taken over by an atomic rename that is verified against the file judged stale, a live one still exits `75`, and a directory where neither works fails with advice to use a local state directory. git exposes no HTTP connect timeout, so the connect phase keeps curl's own bound.
- Clones use a sparse index (git 2.37+, required on Windows), so a Windows-invalid path inside a skill nobody selected no longer makes checkout fail on Windows.
- `--allow-mass-removal`: an update without selection flags that would remove more than half of a client's managed skills (at least 20) leaves that client as it is and exits `3` unless this flag is given (the other client still updates), so exit `3` always means a person must act. `SKILLS_KEEP_BACKUPS` (default 5) bounds the retained transaction journals, with the copies of a backup that keeps them (see Changed: a finished update from the git library keeps none); they are ordered by their `time_ns` stamp (names now use UTC), and every kept journal is checked for an interrupted update.
- The weekly sync rejects upstream skills the installer could not install on every platform (Windows-invalid or reserved names, case-only collisions, symlinks, `.gitattributes`/`.gitmodules`, unreadable frontmatter) before they reach `skills/`, gives a case-only ID twin a source-qualified variant ID, commits the valid rest and then fails the workflow run. A rule-breaking tree or an index-regeneration failure stops the sync before anything is committed.
- CI runs on `ci/**` branch pushes, lints `install.sh` with shellcheck, and runs the installer, git transport and bootstrap tests on `windows-latest` and `macos-latest` as well as Ubuntu.

### Changed
- **A finished update keeps no copies.** Every folder an update moves into `backups/<stamp>/` is a managed copy whose fingerprint matched (an edited copy is never replaced), which the library can make again, so once the transaction is complete the installer deletes those folders and keeps its `restore.json`, without the ownership manifests, as a small record. The backup stays what it was for while the transaction runs: an interrupted update is still rolled back by the next run, and one that cannot be because a file was edited since still exits `3` naming the `--restore` that undoes it. A backup keeps its copies where the library's git history does not hold every one, judged by the trees in the clone: copies made from a local `--source` tree, and any whose origin its journal does not record (the tarball installer's records have no tree); those restore as before (later transactions of the same client first, until one of those keeps no copies, when the refusal names the selection flags) and are pruned by `SKILLS_KEEP_BACKUPS`. The journal is marked dropped before any deletion, so `--restore` of it refuses with one message naming the selection flags (`--selection`, `--manual`, `--enable`, `--disable`, which install from the library again; for a migration, the command its line printed, made again from the v1 selection the journal keeps, which also replaces the `--claude-only --restore BACKUP` that an earlier build of this release (commit 4cc8390e) printed for a long Claude list) and a later run finishes an interrupted deletion. Every update run, one with nothing to change included (not `--dry-run`, `--list`, `--restore`, or one that leaves both clients to a person), also empties the finished backups an earlier version kept, the v1 installers' and the migration's included, so a host that migrated gets its 300 MB back at its next refresh; one still applying is never touched, nor one a `--restore` has begun on (one client's part restored, or a restore cut short) while the rest can still be restored. A backup still preparing, or without a journal, belongs to a run that died before moving anything live, and the same pass deletes what it prepared (a killed migration's: the whole library). Real runs print `Recovery backup: BACKUP` only for a backup `--restore` can still use.
- **The router is per client** and searches through the launcher: Claude's takes the request as `$ARGUMENTS`, may run only the launcher's `search` (`allowed-tools`), invokes visible matches and asks you to type `/ID` for hidden ones; Codex's reads the printed `SKILL.md` and points at `$ID`. Claude now gets the router too. It no longer tells the model to enable skills.
- Codex no longer deduplicates identical aliases or refuses different-content variants that share a frontmatter name: each installs under its own ID. A skill outside the library that already holds a name keeps it; the library copy is then not installed for Codex unless its ID is asked for by name, which stops the run.
- The default Codex root is `$CODEX_HOME/skills` when `CODEX_HOME` is set (a saved destination still wins). The installer now writes one folder in `~/.agents/skills`, `awesome-skills`, Codex's second root.
- A run with more than 100 actions prints one summary line per client instead of the JSON plan.
- **Requirements:** remote installs need git 2.29 or newer (2.37 on Windows); a missing or older git fails before anything is written. Local installs from a complete checkout still need no git.
- **Requirements:** remote installs and updates (both bootstraps, and the helper the router runs) need only the Python 3.11+ standard library. PyYAML is needed only to install from a checkout or `--source` tree, which reads every `SKILL.md` in full, and for `scripts/sync_skills.py`; without it such an install fails once, before any lock or write, with a message naming that path.
- `--list` reports git `tree` ids instead of the former whole-tree `sha256` per skill, and reads the clone offline as of its last update. `--dry-run` fetches new commits and trees into the clone and plans against the remote tip without writing state or destinations or moving the checkout; both may lazily fetch objects into the clone, and in remote mode both need an existing install.
- An unmanaged directory is adopted only as an exact copy in a form only this installer writes (this install's router included), or as an exact library tree when its ID is named in a set (`@all` names none) outside Codex's second root; any other is never adopted or removed, even when identical to a library skill (pre-manifest copies and other tools' copies are left alone). Inherited `GIT_*` variables and system/global git attributes no longer reach the installer's git commands. Only SHA-1 libraries are supported.
- Real runs print the JSON plan only when something changed. The router no longer points into a cache: it runs the helper inside the library clone (or, for a local install, the checkout's helper with `--source`).
- A run interrupted while downloading or preparing copies leaves a `preparing` journal that does not block later runs; `--restore` of such a journal is a no-op. Only the newest journal is read to look for an unfinished transaction.
- State and recovery journals are read and written as UTF-8 on every platform.
- README headline counts are now **derived dynamically** from the live skill tree on every sync instead of hand-maintained. `scripts/sync_skills.py` gained `update_readme_counts()`, which rewrites the skills badge + intro/bootstrap prose (rounded `<floor>+`, e.g. `1,900+`), the repo-layout tree line (exact count, e.g. `1,973`), and the sources badge/intro/heading (`len(UPSTREAMS)`). The substitution is idempotent; `main()` calls it after each sync and the `sync-skills` workflow now stages `README.md` alongside `skills/`. Covered by `tests/test_readme_counts.py` (5 cases).
- `scripts/verify_codex_catalog.py` and its tests use neutral `external-linked` and `external-copied` fixtures in place of `sherlock-kit` and `microsoft-foundry`. Their purpose is unchanged: two skills outside the library, one exposed through a symlink in the temporary `~/.agents/skills`, must stay model-visible with their descriptions after migration.

### Removed
- The per-run tarball download and the `~/.cache/awesome-skills/libraries/<snapshot>` cache. `SKILLS_CACHE_DIR` now only locates old snapshots for removal.

### Migration
- **Stored selections migrate once, automatically**, at the next run, under the lock and in a normal transaction: Claude's former default `@all` becomes the router visible with the library hidden (`Migrated claude: @all -> visible @library, 2300 hidden; undo: --claude-only --selection @all`), as does a Claude list of more than 99 IDs naming most of the library, which is how v1 stored `@all` after a `--disable` (its line abbreviates the list and gives the shorter of `--claude-only --selection @all --disable ID ...`, one `--disable` for each library ID the v1 list does not name, that is those it left out and those added since, and the list itself as the undo, without IDs that left the library); any other selection, for either client, stays visible with the rest of the library installed hidden (undo: `--manual ''`). The migration itself removes nothing, so the mass-removal guard does not fire, and the run exits `0`; the same transaction removes the copies of IDs the library no longer has, which the line names. The line and the dry-run report give the sets the run leaves, without saved IDs that left the library (dropped with one warning). Each printed undo is a selection command, which needs no backup and leaves a state of this version, so the migration never runs again. `migrations.json` in the state directory records the migration once its transaction is complete; an interrupted one is recovered and redone. A migration from the git library keeps no copies once complete (its backup held about 300 MB for the whole library); where its backup keeps them (a migration from a local `--source` tree), a `--restore` of it is a lasting opt-out (the old selection, nothing hidden), marked `undone` in `migrations.json`, and markers already written stay honored. `--dry-run` reports it.
- Existing installs made by the tarball installer are recognized from their ownership manifests: a managed copy whose bytes and executable bits match the current library tree is recorded with its tree id and not copied again (tarball permission bits such as `0664` do not force a copy); modified managed copies stay preserved; the old router is replaced. Once no managed router comes from the old installer, the snapshot directories it created under `~/.cache/awesome-skills/libraries/` (64-hex names with the exact snapshot layout, and their `.tmp-` siblings) are removed. Nothing else is deleted. The first run downloads the blobs of selected skills once.
- The library skill `skill-creator` (from anthropics/skills) is now `skill-creator--anthropics-skills--ad87867d4b`, and `claude-api`, `deep-research` and `security-review` are now `claude-api--anthropics-skills--a7e8254e41`, `deep-research--legacy--560424e232` and `security-review--legacy--42f7f2b05f`, so `/claude-api`, `/deep-research` and `/security-review` run Claude Code's own again. The migration line names the copies the same run removes, for example `, 4 removed (claude-api,deep-research,security-review,skill-creator)`; where the migration's backup keeps its copies (a local `--source` tree), restoring it after a later transaction names the later ones to restore first, newest first. Claude's default `@all` selection replaces the old copy with the new one. A saved selection or hidden set that names an ID the library no longer has, such as `skill-creator`, now drops it with a warning instead of failing every run for both clients; enable the new ID to keep it visible.

### Fixed
- **Security:** `install.sh` took any `scripts/install_skills.py` beside it for a checkout's installer and ran it. The dotfiles payload hook stages `install.sh` as a plain file directly in `$TMPDIR`, which is the shared `/tmp` on multi-user hosts and cluster login nodes, so anyone could plant `/tmp/scripts/install_skills.py` and have it run as the owner at the next weekly run, which still exited `0`; `install.ps1`, which suggests saving itself in the temporary folder (`/tmp` off Windows), had the same rule. Both now run an adjacent installer only from a checkout (`skills/` or `.git`) that the user owns and no one else may write to, `scripts/` and each Python file in it included (the installer of a local tree runs `sync_skills.py`, the launcher `search_skills.py`; group write only for the user's private group); otherwise they say so and download the installer.
- **Security:** the weekly sync copied upstream files with `shutil.copy2`, which follows links: a link to an absolute path (the runner's `.git/config` with its token header, `/dev/zero`) became a regular file holding the target's bytes, which the job would have committed and pushed. A file link is now followed only to a regular file of the same upstream checkout outside its `.git`; any other is copied as a link and the skill rejected, without reading through it. A linked `.gitattributes` is not read for LFS patterns either: one linked to a FIFO hung the job.
- **Security:** PyYAML and Python's `str.splitlines()` break lines at U+2028, U+2029, NEL and a few control characters, which Claude Code and Codex read as part of the line. An upstream `description: a<U+2028>extra: b` passed every check as two keys and reached Claude Code as one line it could not parse, so it dropped the frontmatter, `disable-model-invocation` included: the hidden copy was listed to the model with text of the author's choosing and the Skill tool ran it, on every default install, after an unreviewed weekly sync. The sync now rejects such a frontmatter (or `agents/openai.yaml`), and the installer reads frontmatter lines only at LF, CR and CRLF and makes no copy of one; no current library skill holds such a character.
- On Windows, git was looked up with `shutil.which`, which searches the current folder first, and a local checkout's revision check ran a bare `git`: a `git.exe`, `git.bat` or `git.cmd` in the folder the launcher ran from (a project, when a session runs it) would have run. git is now taken only from an absolute `PATH` folder, with `PATHEXT`, and run by that path.
- PowerShell ends a single-quoted string at `‘`, `’`, `‚` and `‛` too, not only at `'`: a data, state, Python or `--source` path such as `C:\Users\O’Brien` broke `awesome-skills.ps1` and the Windows router forms, and one holding `’+(...)+’` ran its middle as code. All five quote marks are now doubled.
- Planning noted only the first library file a comparison lacked in the blobless clone, so a hidden Codex copy (`SKILL.md`, then `agents/openai.yaml`) or a skill with a nested `SKILL.md` was compared only one run per missing file later: after the data folder was lost, identical copies stayed unproven folders for a run or more. Every file a comparison needs is now noted at once, fetched in the one batch, and the plan made again until nothing more is wanted.
- The documented one-liners (`curl ... install.sh | bash`, `install.ps1`) exited 1 with `awesome-skills requires PyYAML` on hosts without PyYAML (seen on fresh macOS, Fedora 44 and Windows), because the installer imported PyYAML at startup although a remote install reads names and descriptions from `library_index.json`. The top-level `name` it still reads (of a user's own skills, for conflicts, and of each prepared copy, checked against the index) now comes from a standard-library reader that follows PyYAML's scanner where it decides which lines hold top-level keys and what the name scalar is, and refuses the rest (anchors, tags, aliases, explicit keys, tabs outside quotes, a block, flow, multi-line or non-string name, a duplicate name). The weekly sync rejects a skill whose name that reader cannot read exactly as PyYAML does; every one of the current 2,300 skills reads the same.
- Codex copies need an ID Codex can load and mention: at most 64 characters (Codex 0.165 drops a longer skill name) from `A-Z a-z 0-9 _ : -` (`$ID` stops at any other character). The sync shortens the base of a variant ID so that it fits, and rejects an upstream skill whose ID does not; the installer refuses such a Codex copy from a local tree.
- A local `--source` tree, which the sync never checked, could install a copy recorded as hidden that the model still saw: an explicit (`? key`) or escaped `disable-model-invocation: false` overrode the inserted `true`, a column-0 continuation line made Claude Code ignore the whole frontmatter, and a `policy:` line inside a multi-line quoted string took the inserted key. A hidden copy, or any Codex copy, of a local skill is now installed only if the skill passes the sync's own checks (`copy_problems` in `scripts/sync_skills.py`, which `scripts/verify_codex_catalog.py` now copies beside the installer); otherwise the run exits `1` naming it.
- `.github/dependabot.yml` no longer requests the `github-actions` label, which does not exist in this repo. Dependabot was posting a "labels could not be found" warning on every GitHub Actions update PR.
- `scripts/install_skills.py` no longer reserves the names `sherlock-kit`, `microsoft-foundry` and `foundry`. If the weekly sync had brought a library skill with one of them, Claude's default `@all` selection would have installed and recorded it on the first run, and every later run would then have rejected the manifest with `Invalid ownership record`. The generic rules are unchanged: hidden entries (including Codex's `.system`), top-level symlinks, unknown and modified entries are preserved, nothing in `~/.agents` is written but this installer's own `~/.agents/skills/awesome-skills` (Codex's second root), and Codex still refuses or skips a selection whose frontmatter name collides with another skill.
- 29 library skills had a multi-line double-quoted `description` whose continuation lines start at column 0: the sync's own sanitizer wrote them when it collapsed valid `>`/`|` block scalars (22 in the 0.3.1 cleanup, 7 at later syncs). PyYAML reads them, but Claude Code rejects the whole frontmatter and then loads the skill with no fields at all, so `disable-model-invocation` would have no effect on them. The sanitizer now indents such lines two columns past their block, which YAML folding ignores (values are unchanged), and the sync rejects a skill that still has the shape. The 29 files were migrated once the same way; PyYAML's whole frontmatter and the standard-library name reader read every one of the 2,300 skills exactly as before, and `library_index.json` is unchanged. Block scalars are still collapsed to the same bytes as before: changing the sanitized form of an upstream skill would add a duplicate variant of every legacy or shared copy at the next sync.
- The sanitizer escapes the characters a double-quoted scalar must not hold raw (control characters, carriage return, and the NEL/LS/PS breaks only YAML 1.1 folds), and measures a double-quoted description as YAML reads it, so an escape counts once in the 1,024-character cap and is not escaped twice when the value is trimmed.
- Git commands that need no repository (`--version`, `config --get core.sshCommand`, `ls-remote` when healing a clone, `clone`) ran in the temporary directory with discovery free to climb: a `.git` another user planted there was honored where the global config trusts every directory (`safe.directory=*`), so its `url.*.insteadOf` could answer for the library and its `core.sshCommand` or credential helper ran. They now run in an empty folder inside the installer's own `mkdtemp` folder, with `GIT_CEILING_DIRECTORIES` naming that folder (never a drive root). A local tree's revision and sparse-checkout guard read only the checkout's own `.git`; the sync's git commands look for no repository above their folder; `scripts/verify_codex_catalog.py` gives Codex a project root of its own, since Codex reads the `.agents/skills` of the nearest `.git` above its working folder.
- `install.sh` ran the downloaded installer as `python -c`, which puts the caller's working directory first on `sys.path` (a `json.py` there was imported), and `install.ps1` from the temporary folder, which came first instead. A downloaded installer now runs with `-I`, a checkout's and the launcher's with `-P`, and both bootstraps check for Python 3.11+ first.
- `install.sh` gives the downloaded installer to Python on standard input instead of as one argument, which Linux limits to 128 KiB; the installer no longer has to stay under a size budget. It is now over that limit, so an `install.sh` saved before this change exits `126` (`Argument list too long`) with it: download `install.sh` again. A copy served from the CDN's cache just after the change heals by itself at the next run. Run that way `__file__` is `<stdin>`, which the installer no longer takes for a file in the caller's folder (whose parent counted as the library clone when it looked like one). A local install without a file of its own (its text on standard input or as `python -c`) is refused before anything is written, instead of leaving a launcher and a pre-approved router that ran a `search_skills.py` from whatever folder they ran in.
- A local `--source` skill with a symlink anywhere (outside the dropped plugin folders) gets no Codex copy: Codex follows directory links, so a `SKILL.md` reached through one entered the model's catalog under its own name and could duplicate a library name. The run exits `1` naming it; Claude's copies keep their links.
- The weekly sync checks every `agents/openai.yaml` a Codex copy gives the policy, so a nested skill's own file must keep its other fields (interface, MCP dependencies) once merged; nothing tested that merge before.
- `scripts/sync_skills.py --sanitize-only` on the library now leaves what a sync would: the recorded digest of each unmodified copy it rewrites follows the new content (before, the stale digest made the next sync treat the copy as locally modified and add a duplicate variant), skills on reserved IDs are moved, and `library_index.json` is regenerated.

## [0.3.1] — 2026-05-20

### Fixed
- `scripts/sync_skills.py` now sanitizes SKILL.md frontmatter so the strict Codex skill loader accepts every file:
  - **Length cap.** `description` > 1024 chars is smart-trimmed at a sentence or word boundary (4 upstream skills fixed: `tooluniverse-variant-analysis`, `tooluniverse-single-cell`, `hugging-science`, `strategist`).
  - **Mid-value colon quoting.** `key: value: with colon` is double-quoted to avoid being parsed as a nested mapping.
  - **Broken folded-scalar collapse.** Upstream typos like `description: ">"` followed by indented body lines are collapsed into a single quoted scalar honoring `>` / `>-` / `>+` / `|` / `|-` / `|+` fold semantics (~38 files: `alphafold`, `pdb`, `chai`, `boltz`, `blueprint`, …).
  - **Flow-collection passthrough.** `tags: [a, b]` and `metadata: {x: 1}` are no longer corrupted into strings; their parsed `list` / `dict` types are preserved.
  - **Multi-line quoted scalar passthrough.** A `description: "first half\n\nsecond half"` block is left intact instead of being double-wrapped.
  - **Synthesize frontmatter when missing.** Upstream `scholar-evaluation` shipped as pure markdown with no `---` block; the Codex loader was skipping it. The sanitizer now generates `---\nname: <dir>\ndescription: "..."\n---` from a heuristic over the body (preferring `## Overview` / `## Description` / `## About` / `## Summary` sections, falling back to the first paragraph or H1).
- Sanitizer is idempotent: a second `--sanitize-only` pass touches 0 files.
