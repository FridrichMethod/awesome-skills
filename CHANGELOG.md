# Changelog

All notable changes to this project are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) where applicable. Skill content versions are tracked upstream.

## [Unreleased]

### Added
- **Incremental git transport for remote installs.** The library is now a git partial clone (`--filter=blob:none`) with a cone-mode sparse checkout in the data directory, `${XDG_DATA_HOME:-~/.local/share}/awesome-skills/library` (`%LOCALAPPDATA%\awesome-skills\library` on Windows), instead of a full `main` tarball downloaded into memory on every run. An update fetches only new commits and trees; only the blobs of selected skills whose git tree changed are downloaded, through a sparse checkout narrowed to exactly those skills and narrowed back afterwards. With nothing changed a run is one `git fetch`, writes nothing (no file, mtime or manifest change), and prints the single line `Already current; selection preserved.`
- Per-skill change detection by git tree id: ownership records now store the `tree` they were installed from, and an unchanged, present skill costs one `lstat`. Destination hashing happens only for entries that changed, are missing, or are (de)selected, so updating one changed skill in a 2,233-skill Claude install took 0.55 s against a local `file://` remote (no-op: 0.16 s).
- `library_index.json`, a committed full-library index (every source ID's frontmatter name and description) generated by `scripts/sync_skills.py` (also `--index-only`) and verified in CI. `--list`, `--search` and the router read it with `library_sources.json`, so searching never downloads skill bodies; a skill missing from the index is skipped with a warning.
- `install.ps1`, a native Windows bootstrap (PowerShell 7, also 5.1) with the same flags as `install.sh`. `scripts/install_skills.py` runs on native Windows: no unconditional `fcntl` import, an `msvcrt` lock, `git -c core.longpaths=true`, extended-length paths for deep skill trees, plain copies, junctions treated like symlinks.
- The installer's own lock is held across fetch, planning and apply; a concurrent run exits with status `75`. Exit codes are now `0` success (including already current), `1` error, `2` usage error, `3` an interrupted update needs a person, `75` locked.
- Env overrides `SKILLS_DATA_DIR`, `SKILLS_REPOSITORY_URL` and `SKILLS_INSTALLER_URL`; tests use a local bare repository served over `file://` and never reach the network.
- Unattended-run robustness. An update killed mid-apply is undone automatically at the start of the next run (exit `3` with the `--restore` command when a later edit prevents that); an exception while moving entries rolls back at once. Under the lock, stale git `*.lock` files and partial clones are removed, and a clone that fails for a reason other than an unreachable remote is moved to `library.broken-<time>` (one kept) and cloned again once, also when a blob download fails. Library entries that cannot be checked out everywhere, or are missing from the index, are skipped with a warning and installed copies of them are frozen; a skill whose copy fails to prepare or verify is skipped while the others update, and the run exits `1`.
- A stalled connection can no longer keep the lock: git transfers abort below 1000 bytes/s for 60 s (`GIT_HTTP_LOW_SPEED_*` override) and, unless ssh is configured for git, ssh runs with `BatchMode=yes`, `ConnectTimeout=30` and keepalives. Where `flock` fails as unsupported (NFS or Lustre homes), an atomic `mkdir` lock records host and pid; it is stale after 6 hours or when its process on the same host is gone, a live one still exits `75`, and a directory where neither works fails with advice to use a local state directory.
- Clones use a sparse index (git 2.37+, required on Windows), so a Windows-invalid path inside a skill nobody selected no longer makes checkout fail on Windows.
- `--allow-mass-removal`: an update without selection flags that would remove more than half of a client's managed skills (at least 20) is refused unless this flag is given. `SKILLS_KEEP_BACKUPS` (default 5) bounds the retained transaction backups.
- The weekly sync rejects upstream skills the installer could not install on every platform (Windows-invalid or reserved names, case-only collisions, symlinks, `.gitattributes`/`.gitmodules`, unreadable frontmatter) before they reach `skills/`, gives a case-only ID twin a source-qualified variant ID, commits the valid rest and then fails the workflow run. A rule-breaking tree or an index-regeneration failure stops the sync before anything is committed.
- CI runs on `ci/**` branch pushes, lints `install.sh` with shellcheck, and runs the installer, git transport and bootstrap tests on `windows-latest` and `macos-latest` as well as Ubuntu.
- New upstream source: [AIScientists-Dev/academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer) (485 ⭐, MIT, 1 skill — `academic-humanizer`: improves the clarity and voice of AI-assisted academic prose and grant proposals (NSF Project Summary/Description, NIH Specific Aims) while preserving scholarly conventions, tying claims to evidence, and never altering a number, result, or citation).

The skill ships as a single root-level `SKILL.md`, so its install directory takes the source's `local_name` (`academic-humanizer`); the name is unique, so it adds with **zero collisions**.

### Changed
- **Requirements:** remote installs need git 2.29 or newer (2.37 on Windows); a missing or older git fails before anything is written. Local installs from a complete checkout still need no git.
- `--list` reports git `tree` ids instead of the former whole-tree `sha256` per skill, and reads the clone offline as of its last update. `--dry-run` fetches new commits and trees into the clone and plans against the remote tip without writing state or destinations or moving the checkout; both may lazily fetch objects into the clone, and in remote mode both need an existing install.
- An unmanaged directory is adopted only when it is selected; an unselected one is never adopted or removed, even when identical to a library skill (pre-manifest copies are left for the user to remove). Inherited `GIT_*` variables and system/global git attributes no longer reach the installer's git commands. Only SHA-1 libraries are supported.
- Real runs print the JSON plan only when something changed. The router no longer points into a cache: it runs the helper inside the library clone (or, for a local install, the checkout's helper with `--source`).
- A run interrupted while downloading or preparing copies leaves a `preparing` journal that does not block later runs; `--restore` of such a journal is a no-op. Only the newest journal is read to look for an unfinished transaction.
- State and recovery journals are read and written as UTF-8 on every platform.
- README headline counts are now **derived dynamically** from the live skill tree on every sync instead of hand-maintained. `scripts/sync_skills.py` gained `update_readme_counts()`, which rewrites the skills badge + intro/bootstrap prose (rounded `<floor>+`, e.g. `1,900+`), the repo-layout tree line (exact count, e.g. `1,973`), and the sources badge/intro/heading (`len(UPSTREAMS)`). The substitution is idempotent; `main()` calls it after each sync and the `sync-skills` workflow now stages `README.md` alongside `skills/`. Covered by `tests/test_readme_counts.py` (5 cases).
- `scripts/verify_codex_catalog.py` and its tests use neutral `external-linked` and `external-copied` fixtures in place of `sherlock-kit` and `microsoft-foundry`. Their purpose is unchanged: two skills outside the library, one exposed through a symlink in the temporary `~/.agents/skills`, must stay model-visible with their descriptions after migration.

### Removed
- The per-run tarball download and the `~/.cache/awesome-skills/libraries/<snapshot>` cache. `SKILLS_CACHE_DIR` now only locates old snapshots for removal.

### Migration
- Existing installs made by the tarball installer are recognized from their ownership manifests: a managed copy whose bytes and executable bits match the current library tree is recorded with its tree id and not copied again (tarball permission bits such as `0664` do not force a copy); modified managed copies stay preserved; the old router is replaced. Once no managed router comes from the old installer, the snapshot directories it created under `~/.cache/awesome-skills/libraries/` (64-hex names with the exact snapshot layout, and their `.tmp-` siblings) are removed. Nothing else is deleted. The first run downloads the blobs of selected skills once.

### Fixed
- `.github/dependabot.yml` no longer requests the `github-actions` label, which does not exist in this repo. Dependabot was posting a "labels could not be found" warning on every GitHub Actions update PR.
- `scripts/install_skills.py` no longer reserves the names `sherlock-kit`, `microsoft-foundry` and `foundry`. If the weekly sync had brought a library skill with one of them, Claude's default `@all` selection would have installed and recorded it on the first run, and every later run would then have rejected the manifest with `Invalid ownership record`. The generic rules are unchanged: hidden entries (including Codex's `.system`), top-level symlinks, unknown and modified entries are preserved, `~/.agents` is never written, and Codex still refuses or skips a selection whose frontmatter name collides with a skill in `~/.agents/skills`.

## [0.3.1] — 2026-05-20

### Fixed
- `scripts/sync_skills.py` now sanitizes SKILL.md frontmatter so the strict Codex skill loader accepts every file:
  - **Length cap.** `description` > 1024 chars is smart-trimmed at a sentence or word boundary (4 upstream skills fixed: `tooluniverse-variant-analysis`, `tooluniverse-single-cell`, `hugging-science`, `strategist`).
  - **Mid-value colon quoting.** `key: value: with colon` is double-quoted to avoid being parsed as a nested mapping.
  - **Broken folded-scalar collapse.** Upstream typos like `description: ">"` followed by indented body lines are collapsed into a single quoted scalar honoring `>` / `>-` / `>+` / `|` / `|-` / `|+` fold semantics (~38 files: `alphafold`, `pdb`, `chai`, `boltz`, `blueprint`, …).
  - **Flow-collection passthrough.** `tags: [a, b]` and `metadata: {x: 1}` are no longer corrupted into strings; their parsed `list` / `dict` types are preserved.
  - **Multi-line quoted scalar passthrough.** A `description: "first half\n\nsecond half"` block is left intact instead of being double-wrapped.
  - **Synthesize frontmatter when missing.** Upstream `scholar-evaluation` shipped as pure markdown with no `---` block; the Codex loader was skipping it. The sanitizer now generates `---\nname: <dir>\ndescription: "..."\n---` from a heuristic over the body (preferring `## Overview` / `## Description` / `## About` / `## Summary` sections, falling back to the first paragraph or H1).
- Sanitizer is idempotent: a second `--sanitize-only` pass touches 0 files.

### Added
- `scripts/sync_skills.py --sanitize-only` CLI flag to normalize the existing `skills/` tree without running an upstream sync. Reports `sanitized`, `synthesized`, and `unrecoverable` counts.
- `_synthesize_frontmatter()` and `_extract_description_from_body()` helpers.
- `tests/test_sanitize.py` — **57 pytest cases** across smart-trim, YAML quoting helpers, end-to-end sanitization, idempotency (including a live-tree scan), post-sanitize invariants, and the three synthesis pathways (from `## Overview`, from a body paragraph, and from a dirname fallback).
- `.github/workflows/ci.yml` — runs `ruff check` + `pytest` on every push, PR, and manual dispatch.
- `pyproject.toml` — pytest and ruff configuration, dev dependency group.

### Changed
- Skill count after re-sync: 1,856 → **1,907** (+51 from upstream growth; 33 added, 121 modified, 2 deleted in the 2026-05-20 sync). All 1,907 SKILL.md files parse cleanly under `yaml.safe_load`, every `description` is ≤ 1024 chars, and Codex loads every skill including `scholar-evaluation`.
